# Инфраструктура: диспетчер, исполнители, хранилище

Задача инфраструктуры — превратить разрозненные устройства в одну систему запуска. Исследователь отдаёт
эксперимент и получает результат, не думая, где он считался. Внутри одного запуска работает ядро
(`docs/core_api.md`); всё вокруг — доставка кода и весов, запуск, сбор результатов, учёт — здесь.

Начинаем с простого: сначала запуск одной командой вручную, очередь и агенты — потом.

## Компоненты

| Компонент | Где | Что делает |
|---|---|---|
| Диспетчер | сервер Игоря (~10 ГБ диска, 1 ГБ RAM, работает постоянно) | очередь задач, список устройств, запуск Kaggle, учёт квот и денег, уведомления |
| Запуск на Kaggle | Kaggle, 2× T4 | диспетчер «толкает» задачу через Kaggle API; сессия закрывается сама |
| Агент | ноутбук Игоря и другие свои устройства | «тянет» задачи у диспетчера (устройство за NAT); включается «кнопкой на ночь» |
| Хранилище | организация команды на Hugging Face | сырые результаты, наши кванты, кэш ответов API |
| Уведомления | Telegram-бот | старт, конец, ошибка задачи; одна строка `summary_line` |

Сервер ничего не считает. Модели, данные и крупные результаты на нём не храним. Диспетчер — небольшая
программа на Python и SQLite; память — в пределах ~200 МБ. ClearML, Postgres и стеки из Docker-контейнеров
не помещаются. Claude Code на сервере тоже не запустить: ему нужно от 4 ГБ RAM.

## Задача и её жизнь

Задача: `id`, кто отправил, коммит, путь к `config.yaml`, тип устройства, статус, где выполняется,
время, ссылка на результат, деньги.

```
queued → assigned → running → done
                           ↘ failed | timeout | lost | cancelled
```

- `assigned` — выбран исполнитель (аккаунт Kaggle или агент).
- `running` — исполнитель шлёт сигнал «я жив» (ядро обновляет `heartbeat.json` раз в минуту; агент
  пересылает его диспетчеру, у Kaggle диспетчер опрашивает статус).
- `lost` — нет сигнала дольше 15 минут.
- `timeout` — сработал жёсткий таймаут запуска (на Kaggle — 11 часов, меньше лимита сессии в 12).

Таблицы SQLite: `users` (имя, хэш личного токена, роль), `devices` (тип, владелец, что умеет, когда был
на связи), `kaggle_accounts` (владелец, часы за неделю), `jobs`, `events` (журнал по задачам),
`spend` (деньги API по задачам).

HTTP API диспетчера (у каждого участника личный токен): `POST /jobs`, `GET /jobs/{id}`, `GET /jobs?status=…`,
`POST /jobs/{id}/cancel`, `POST /agents/heartbeat`, `POST /agents/claim`, `POST /jobs/{id}/result`.
Адрес сервера — в секретах, не в репозитории.

## Запуск на Kaggle

Диспетчер собирает папку `jobs/<id>/` с двумя файлами и отправляет её под токеном аккаунта владельца:

```json
{"id": "<user>/job-42", "title": "job-42", "code_file": "launch.py", "language": "python",
 "kernel_type": "script", "is_private": true, "enable_gpu": true, "enable_internet": true,
 "machine_shape": "NvidiaTeslaT4"}
```

`machine_shape: "NvidiaTeslaT4"` — это 2× T4. Ещё есть поля `dataset_sources` и `model_sources` — через них
удобно подключать заранее собранный llama.cpp.

`launch.py` делает по шагам:
1. `git clone` репозитория и `git checkout <commit>`;
2. `pip install -e core`;
3. берёт `HF_TOKEN` и `NEBIUS_API_KEY` из Kaggle Secrets и кладёт в окружение;
4. выставляет `LLAMA_CPP_BIN` (сборка под CUDA sm75, подключённая как Kaggle Dataset) и
   `FASTINFER_CACHE=/tmp/fastinfer-cache` — веса не в `/kaggle/working`, иначе попадут в вывод;
5. `timeout 11h python -m fastinfer.run <config> --out /kaggle/working/results --job-id 42 --commit <sha>`.

Команды:
```
kaggle kernels push -p jobs/42/
kaggle kernels status <user>/job-42
kaggle kernels output <user>/job-42 -p results/42/
```

Команды остановки в документации Kaggle CLI нет — поэтому таймаут в самом скрипте. Вывод сессии — то, что
записано в `/kaggle/working`.

llama.cpp с CUDA на 4 ядрах собирается долго: собрать один раз под sm75 и хранить как Kaggle Dataset
(или на HF), версию — записывать в `env.json`.

## Агент для своих устройств

- Одна команда, чтобы подключить устройство, и одна — чтобы отключить: `fi-agent up --device laptop-780m`,
  `fi-agent down`. «Кнопка на ночь» — ярлык, который запускает агента и не даёт ноутбуку уснуть.
- Агент регистрируется, шлёт сигнал «я жив», забирает задачи под своё устройство (`POST /agents/claim`).
- Выполняет **только код из репозитория команды** на коммите из `main` или из PR, который одобрен;
  диспетчер это проверяет.
- Работает в отдельной копии репозитория: `git fetch`, `git checkout <commit>`, запуск ядра с таймаутом,
  отправка `result.json` диспетчеру, сырых файлов — на HF.
- Кроссплатформенный Python: ОС ноутбука Игоря уточнить; на 780M — llama.cpp с Vulkan.

## Хранилище

- Организация команды на Hugging Face, бесплатно 100 ГБ приватного хранилища. Один файл — до 500 ГБ
  (рекомендуют меньше 200 ГБ); в репозитории — меньше 100 тыс. файлов, в папке — меньше 10 тыс.
- Датасет `results`: папка на задачу (`per_prompt.jsonl`, `env.json`, логи).
- Датасет `api-cache`: ответы Nebius, чтобы одинаковый запрос не оплачивать дважды.
- Наши кванты — в модельных репозиториях. Исходные веса Nemotron качаем из репозиториев NVIDIA и не копируем.
- В GitHub — только сводки: результат приходит PR-ом от бота, в `main` бот не пишет.

## Деньги и квоты

- Nebius: $150 только на API Token Factory. Диспетчер ведёт общий счёт по `spend`, ставит каждой задаче
  `FASTINFER_API_CAP_USD` и не запускает задачу, если её оценка (`--dry-run`) не помещается в остаток.
- Kaggle: ~30 ч в неделю сессий с GPU на аккаунт, до 12 ч на сессию. Диспетчер считает часы по аккаунтам
  и выбирает аккаунт с запасом. Как именно Kaggle считает квоту при 2× T4 — проверить по счётчику.

## Секреты

- Токены Kaggle, HF, Nebius и Telegram — в файле окружения на сервере (права 600), в Kaggle Secrets
  и в GitHub Secrets. В репозитории и логах — никогда. Push protection включён.
- У каждого участника личный токен диспетчера.
- Агент выполняет только код команды из проверенных веток.

## Правила

- Один аккаунт Kaggle и Colab на человека. Бесплатный Colab — только вручную: его правила запрещают
  удалённое управление и воркеры распределённых вычислений.
- Скорость сравниваем только на одном типе железа — поэтому в конфиге указано устройство.
- Санкционные ограничения не обходим.

## Этапы

| Этап | Что делаем |
|---|---|
| 0 | `launch.py` и ручной запуск на Kaggle одной командой; сборка llama.cpp как Kaggle Dataset |
| 1 | диспетчер: приём задач, очередь, запуск Kaggle, Telegram |
| 2 | агент для ноутбука |
| 3 | HF: результаты и кэш API; учёт денег и квот |

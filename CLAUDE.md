## Что это за проект

Команда из трёх начинающих ускоряет инференс (генерацию ответов) моделей NVIDIA Nemotron на доступном
бесплатном железе и выясняет, от чего зависит результат. Каждое ускорение проверяем и по скорости,
и по качеству ответов. Цель — не одна техника, а карта: что, где и насколько ускоряет.

| Группа | Модели | Где считаем |
|---|---|---|
| 1. Плотные гибриды Mamba-Transformer | Nemotron Nano 9B v2, Nemotron 3 Nano 4B | Kaggle 2× T4, ноутбук |
| 2. MoE, которые запускаются у себя | Nemotron 3 Nano 30B-A3B, Lightning 3.5 (30B-A3B) | ноутбук Игоря (Radeon 780M), Kaggle 2× T4 |
| 3. Super | Nemotron 3 Super 120B-A12B, Nemotron 3.5 Super VL | только API Nebius; «ускоряем через Nano» |

Super доступен только через API: по нему можно мерить согласие моделей (как часто Nano угадывает
токены Super), число токенов и деньги, но не скорость по времени. Бюджет Nebius — $150.

## Команда и роли

- **Игорь** ведёт проект. Ноутбук: 32 ГБ общей памяти и Radeon 780M. Сервер: ~10 ГБ диска, 1 ГБ RAM,
  работает постоянно — на нём только диспетчер.
- **Руслан** — лёгкий Mac. **Дима** — ПК на Windows, 16 ГБ.
- У каждого ~4 часа в день и свой аккаунт Kaggle. Аренду GPU не используем.
- Роли: **исследователь** (идеи, эксперименты на функциях ядра, выводы), **разработчик ядра**
  (библиотека `fastinfer`), **инфраструктурщик** (диспетчер, запуск на Kaggle и ноутбуке, хранилище).
  Кто какую роль занимает: _заполнить_.

## Правила, которые нельзя нарушать

1. **Секреты** — токены Kaggle, Hugging Face, Nebius, Telegram, адрес сервера — только в GitHub Secrets,
   Kaggle Secrets и в файле окружения на сервере. Никогда в коде, конфигах, логах, ноутбуках и выводе тестов.
   В репозитории включён push protection.
2. **Без тяжёлых файлов.** Не кладём веса, датасеты и файлы больше 50 МБ (GitHub блокирует от 100 МБ).
   Сырые результаты — на Hugging Face, в репозитории — только сводки.
3. **Через PR.** Бот и любая автоматика не коммитят в `main`.
4. **Контракт ядра общий.** `core/fastinfer/types.py`, `core/fastinfer/engines/base.py`, сигнатуры
   в `core/fastinfer/__init__.py`, форматы `config.yaml` и папки результата меняются только через PR,
   который смотрят все трое.
5. **Внутренности ядра пишет разработчик ядра.** Он хочет разобраться сам. Не реализуй модули ядра,
   пока он прямо не попросит; заготовки, сигнатуры, docstring и тесты контракта — можно.
6. **Тесты не ходят в сеть и не тратят деньги.** По умолчанию `pytest` не зовёт Nebius и не качает модели.
   Такие тесты помечаются `network` или `paid` и по умолчанию выключены.
7. **Правила площадок.** Один аккаунт Kaggle и Colab на человека; бесплатный Colab не подключаем
   как исполнитель; санкционные ограничения не обходим — никаких чужих номеров и VPN.
8. **Деньги Nebius** ($150) — только на API Token Factory. Код, который зовёт API, оценивает стоимость
   до запуска, ведёт учёт и останавливается на потолке.

## Как мы мерим

- При генерации по одному запросу скорость упирается в память: потолок ток/с ≈ пропускная способность
  памяти ÷ байты, прочитанные на токен. В каждом замере пишем долю от потолка.
- База и варианты — в одном запуске, на одном устройстве; повторы чередуются; прогрев не считается.
- Для скорости: батч 1, жадный выбор, `cache_prompt: false`, одинаковые промпты и `max_tokens`.
- «Без потерь» проверяем сравнением ответов с базой. Небольшие расхождения бывают и при правильном коде —
  путь «по одному токену» и путь проверки считают по-разному
  (`experiments/2026-10-15-mamba-rollback-check`). Поэтому в месте расхождения смотрим отрыв между
  двумя лучшими токенами у базы.
- Методы, которые меняют ответы, — всегда со скоростью и точностью вместе.

Полностью — `docs/core_api.md`, раздел «Правила замера».

## Технические опоры

- **llama.cpp** — основной движок: CUDA на T4, Vulkan на 780M, Metal на Mac, CPU на ПК. Сборка
  от 15.10.2026 (коммит 620d222) умеет спекуляцию (`--spec-type draft-simple | draft-mtp | draft-eagle3 |
  draft-dflash | ngram-*`), откат состояния для `nemotron_h` и `nemotron_h_moe`, бюджет рассуждения
  (`--reasoning-budget`).
- **HF transformers 5.19.0** — нативный NemotronH. Встроенный assisted generation для моделей с состоянием
  не работает: спекуляцию в HF делаем своим циклом с откатом состояния Mamba.
- **API Nebius** — OpenAI-совместимый, `https://api.tokenfactory.nebius.com/v1/`, ключ `NEBIUS_API_KEY`.
- **T4** — sm75: только fp16 (нет bf16), нет FP8, FlashAttention-2 и ядер Marlin; две карты без NVLink.

Цифры и источники — `docs/facts.md`.

## Стиль

- Документация, комментарии и сообщения коммитов — по-русски и коротко; имена в коде — по-английски.
- Python 3.10+, типы на всех публичных функциях, dataclass вместо словарей там, где это контракт.
- Зависимости ядра минимальные (pyyaml, numpy, httpx, huggingface_hub); torch, transformers и openai —
  необязательные extras.
- ruff для стиля, pytest для тестов, CI на GitHub Actions (CPU).

## Чего не делать

- Не подгонять цифры: никаких сравнений со слабой базой, выборочных прогонов без записи и округлений в свою пользу.
- Не ставить на сервер тяжёлое (там 1 ГБ RAM): никаких ClearML, Postgres и стеков из Docker-контейнеров.
- Не класть веса в `/kaggle/working` — это папка вывода Kaggle.
- Не менять контракт ядра молча.
